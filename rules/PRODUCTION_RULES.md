## 2. コマ数の方針

### 2.1 基本フォーマット

- 1話 **5〜8枚**
- 1枚 **3〜5コマ**
- 既定値は **24コマ（6枚 × 4コマ）**

### 2.2 コマ予算

| 区分 | 値 | 扱い |
|---|---|---|
| 既定値 | 24コマ | 何も考えなければこれ |
| 目安 | 平均20〜25コマ | Season通算でこの平均に収める |
| 標準レンジ | 18〜28コマ | この中なら自由 |
| 許容レンジ | 15〜40コマ | 外れる場合は `meta.yaml` の `panel_budget_reason` に理由を書く。28超は要理由、40超はエラー |

実際の数値は `management/CONFIG.yaml` の `panel_budget` が正本。

### 2.3 原則（最重要）

> **コマ数を増やすこと＝面白くなること、ではない。**
>
> コマ数はノルマではなく**上限**である。優先するのは、読みやすさ・テンポ・オチ・キャラの魅力・
> SNSでの離脱防止・**制作を続けられること**。
>
> **必要以上にコマ数を増やすことを禁止する。迷ったら減らす。**
>
> - 1コマ1情報。同じ情報を2コマに割らない。
> - 説明のためのコマを足さない（説明が要るなら構成が悪い）。
> - コマを削って成立するなら、それが正しい構成である。
> - コマを増やしたくなったら、まず「話の方を削れないか」を考える。

### 2.4 コマ割りの規則

- 均等割りにしない。
- 各ページに**必ず1つ L コマ**を置く（表情・オチ・驚き・感情の変化・重要セリフのいずれか）。
- セリフは **1コマ最大2吹き出し・1吹き出し最大24文字**（スマホ縦読みで潰れない上限）。
- ページの最終コマは次ページへの引き。

## 3. AI の絶対禁止事項

この7項目に違反すると、この制作システムの安全設計そのものが無意味になる。

1. **`tools/approve.py` を実行しない。** 承認は人間だけの権限。
2. **`management/APPROVALS.log` を編集しない。** 承認の証跡であり、AIが書いた瞬間に証跡ではなくなる。
3. **`git config user.*` を変更しない。`git commit --no-verify` を使わない。**
4. **`canon/` 直下（`_proposed/` を除く）を、承認記録なしに変更しない。**
5. **`docs/` と `episodes/*/prompts/` を手で編集しない。** 再生成される派生物であり、手で直すと二重管理が始まる。
6. **`visual.lock` を言い換えない・書き写さない。** ツールが canon から機械的に解決する。
7. **実在人物の名前・顔・プロフィール・私生活をキャラ設定に流用しない。**

### 3.1 この防御の限界（隠さず書く）

同一マシン・同一ユーザーで動くAIに対して、**暗号学的に完全な防御は原理的に不可能**である。
承認ガード（P6.5で実装予定）の目的は「偽造を不可能にすること」ではなく、
**①通常作業の副作用としては絶対に起きないようにする ②偽造すれば必ず検出可能な痕跡を残す**
の2点である。git hook は `--no-verify` で回避できる。**これは悪意ではなく「うっかり」を止める装置である。**

だからこそ、上の7項目は「機械が止めるから守る」のではなく、**ルールとして守る**。

## 4. 承認の線引き

### 4.1 人間の承認が必要（重要事項のみ）

- キャラクターの名前・年齢・勤務歴・性格の根幹・関係性
- 店舗の基本設定・料金・所在地
- Season全体のテーマ・主人公の到達点・アーク構成
- 伏線の新設・撤回
- 作品コンセプト／`STYLE_GUIDE.md` の方針変更
- 制作モードの変更（REVIEW → AUTO）
- 画像プロバイダの変更
- **公開（PUBLISHED への遷移）**

### 4.2 承認不要（AIが自動で進める）

- 誤字・表記ゆれの修正、ファイル整理・命名・移動
- プロット下書き・脚本・コマ割り案・画像プロンプト生成
- エピソードの status 遷移（PUBLISHED を除く）
- 伏線の「回収済み」への状態更新、キャラの `first_appearance` の記入
- `docs/` の再生成、`PRODUCTION_BOARD.md` の更新、`STATE.md` の更新
- 単発の小道具・モブ客・単発の店の追加（`canon/` ではなく episode 内に置く。**3回以上出たら昇格提案**）
- `IDEA_POOL.md` への追記

### 4.3 変更提案の手順

1. `canon/_proposed/CHG_xxxx_<件名>.md` を作成する
2. 記載内容: 変更対象（ファイル・フィールド）／変更前→変更後の差分／理由／影響調査（該当話とコマを列挙）／矛盾する箇所の一覧／修正案／却下した場合の代替案
3. 人間が読んで承認／却下／修正指示
4. **承認された場合のみ**、AIが `canon/` を書き換え、旧版を `archive/canon/CHG_xxxx/` へ退避し、`CANON.md` の履歴に追記する

**迷ったら「承認が要る」側に倒して提案を書く。勝手に決めない。**

## 5. 制作モード

現在のモードは `management/CONFIG.yaml` の `mode` が正本。

### REVIEW MODE（初期値）

AIは「**本命1本＋控え**」の形で提示する。

- **「常に3案」は禁止。** 代替案は方向が本当に分岐する時だけ出す。**案を増やすことは仕事ではない。**
- 人間が「OK／代替案で／ここだけ直して」で返せる分量にする。

### AUTO MODE

AIが最適と判断した案を選び、次工程へ進める。選択理由を `01_outline.md` の冒頭に必ず記録する。

**AUTO MODE でも必ず人間で停止する7項目（例外なし）**

1. CANON変更（キャラ・世界観・関係性・時系列）
2. 主要キャラクターの設定変更
3. 長期ストーリーの重要変更・作品の方向性を変える変更
4. `key_episode: true` の話
5. 矛盾チェックで**警告以上**が出た話
6. 公開判断（PUBLISHED）
7. 5話ごとの定期レビュー

### モード遷移

- **昇格（REVIEW → AUTO）**: REVIEW で連続3話、人間の修正指示なしで通過＋矛盾チェック3話連続クリーン → AIは**提案するだけ**。確定は人間の承認。
- **降格（AUTO → REVIEW）**: 矛盾チェックでエラー、または人間が2話連続で修正指示 → **AIが自分で戻す**（降格は自己判断でよい）。

## 6. 制作ステータス

```
IDEA → OUTLINE → SCRIPT → STORYBOARD → IMAGE_PROMPT → IMAGE_GENERATION → EDIT → REVIEW → PUBLISHED
```

- `IMAGE_GENERATION` / `EDIT` は**人間の工程**（現行の画像プロバイダが `chatgpt_manual` のため）。
- `PUBLISHED` への遷移は**人間の判断と実行のみ**。
- 飛び越し遷移は禁止（機械チェックで検出する）。

---

## 7. セッション運用

- 作業開始時は `CLAUDE.md` の起動シーケンスに従う。**全部読まない。**
- **作業を止める時は必ず `management/STATE.md` を更新してからコミットする。** 更新せずに終わらない。
- **会話履歴を正本にしない。** 作品の状態はすべてこのディレクトリのファイルにある。
- 実装・変更が通ったら**その場でコミットする**（このリポジトリは並行編集され定期同期されるため、未コミット変更は失われる）。
- コミット前に `git diff --cached` でAPIキー・PII・Windowsパス（`C:\` / `F:\`）が混ざっていないか確認する。

---

## 8. 公開とコンプライアンス

- 作中の人物・店舗は**すべて架空**。実在人物をそのまま主人公にしない。
- 実在店舗の名称・ロゴ・内装を無断でコピーしない。
- キャラクター名・店名・街名は、確定前に実在との被りを検索して確認する（手順は P1 で `DISCLAIMER.md` に定める）。
- 実在のキャバ嬢を紹介するSNSアカウントと、**漫画作品のアカウントは分離する**。
- 公開物に架空の売上・未計測の数値・未達の成果を書かない。
- 公開判断は人間のみ。**AIが投稿を実行しない。**
